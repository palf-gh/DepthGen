## English

DepthGen v1 ships two embedded relative monocular-depth models, selected by the
`Model` popup. ZipDepth Base NPU is the speed option (MIT, 6.1M parameters).
Depth Anything V2 Small is the quality option (Apache-2.0). Larger raw values
generally mean nearer apparent surfaces. The output is relative and does not
promise metric distance.

### Pinned upstream checkpoint

- Repository: <https://github.com/fabiotosi92/ZipDepth>
- Commit: `94da7527f7030a0e79d54f33b113bdce4065d735`
- Checkpoint: `checkpoints/zipdepth_base_npu.pth`
- Checkpoint SHA-256:

```text
627c04fda584133ead4310074884a4a037061b4c01ba86e73e492ea30fab570d
```

The NPU checkpoint is intentional: its convex upsampler avoids
`torch.nn.Unfold` and maps to both DirectML and Core ML. The
`depthgen_fetch_model` target checks out only the pinned revision under
`build/depthgen_upstream/ZipDepth` and rejects a checkpoint hash mismatch.

### Shipped ONNX

The release binary embeds `zipdepth_base_npu_dynamic.onnx`, generated by
`tools/build_zipdepth_model.py`:

- ONNX IR version 8 and opset 17 for ONNX Runtime 1.17.3 compatibility;
- legacy PyTorch exporter (`dynamo=False`);
- dynamic NCHW height and width, with both dimensions aligned to 32 pixels;
- fused inference-time convolution and batch-normalisation branches;
- the upstream export-time global-context, strip-pooling, and cross-scale
  forwards expressed as dynamic reductions and fixed-factor resizes;
- the NPU checkpoint's unfold-free upsampler retained.

The exporter uses a 384×384 example tensor only to trace the graph. Dynamic
axes remain in the ONNX, so Fast/Balanced, High, Custom, landscape, and
portrait renders use the same file. The plug-in concretises those free
dimensions when creating an ONNX Runtime session; this is required for correct
Core ML output and provider optimisation.

The Windows build stores the verified bytes as an `RCDATA` resource. Each
architecture slice of the universal macOS executable stores them in a
read-only Mach-O section. ONNX Runtime loads the model directly from memory;
no ONNX sidecar is installed. The original SHA-256 is verified against the
embedded bytes once before the first session is created.

Shipped ONNX SHA-256:

```text
0741a0d574609da33c5081b1054a2dd1e8845ecdbed9a5f69c48807c22400d59
```

This digest is pinned in `Source/DepthGen_ModelIntegrity.h` and verified before
session creation. A successful check is cached by model path, size, and
modification time. Model files are never downloaded by the effect and are not
stored in Git.

The pinned exporter environment used for this digest was Python 3.12.0,
PyTorch 2.13.0+cpu, and ONNX 1.22.0. `--self-test` additionally used NumPy
1.26.4 and ONNX Runtime 1.17.3; its 384×672 comparison against the fused
PyTorch graph measured MAE `3e-8` and maximum error `1.3e-7`.

### Input and output contract

1. Reduce the premultiplied source directly into an inference-size NCHW tensor
   with alpha-weighted bilinear sampling; fully transparent pixels become
   black for inference.
2. Treat input as sRGB by default, or encode linear input with the sRGB OETF
   when selected.
3. Pass planar RGB in `[0,1]` for ZipDepth. For Depth Anything V2 Small, apply
   ImageNet mean/deviation after that unit-range tensor. ZipDepth performs its
   own internal normalisation; Depth Anything does not.
4. Fast uses a 512-pixel full-resolution short edge, Balanced uses 768, and
   High uses 1080; Custom accepts any whole-pixel value from 256–2160. Preview
   resolution scales the labelled short edge before both model dimensions are
   rounded up to multiples of 32. Consequently FHD and UHD inputs use
   1920×1088 and 3840×2176 model tensors.
5. Bilinearly upsample raw relative depth to the source frame with aligned
   corners, then map robust percentiles to black (far) and white (near).

To regenerate the artefact, install the documented exporter environment, run
`depthgen_fetch_model`, then run `depthgen_build_model` or
`tools/build_zipdepth_model.py --self-test`. A toolchain change that produces a
different digest must be reviewed deliberately; update every manifest, notice,
integrity pin, benchmark, and provider-parity record together.

リリースバイナリは `tools/build_zipdepth_model.py` が生成した
`zipdepth_base_npu_dynamic.onnx` を埋め込みます:

- ONNX Runtime 1.17.3 互換のための ONNX IR バージョン 8 と opset 17;

自由次元を具体化します。正しい Core ML 出力とプロバイダー最適化に必要です。

macOS 実行ファイルの各アーキテクチャ断片は、読み取り専用 Mach-O セクションに
格納します。ONNX Runtime はメモリから直接モデルを読み込み、ONNX サイドカーは
インストールしません。埋め込みバイトに対する元の SHA-256 は、最初のセッション
作成前に一度検証します。

```text

```

このダイジェストは `Source/DepthGen_ModelIntegrity.h` にピンされ、セッション
作成前に検証されます。成功した検査はモデルパス、サイズ、更新時刻でキャッシュ
されます。モデルファイルはエフェクトがダウンロードすることはなく、Git にも
格納しません。

このダイジェストに使ったピン済みエクスポーター環境は Python 3.12.0、

### 入出力契約

1. 事前乗算済みソースを、アルファ加重バイリニアサンプリングで推論サイズの
   NCHW テンソルへ直接縮小する。完全に透明な画素は推論では黒になる。
2. 既定では入力を sRGB として扱う。選択時はリニア入力を sRGB OETF で符号化する。
3. 平面 RGB を `[0,1]` で渡す。ZipDepth が学習済み／内部正規化を行う。ホストは
   ImageNet の平均／偏差を適用しない。
4. Fast はフル解像度短辺 512 ピクセル、Balanced は 768、High は 1080。Custom は
   256–2160 の任意の整数ピクセルを受け付ける。プレビュー解像度はラベルの短辺を
   縮小してから、両モデル次元を 32 の倍数へ切り上げる。したがって FHD と UHD
   入力は 1920×1088 と 3840×2176 のモデルテンソルを使う。
5. 生の相対深度を角を揃えたバイリニアでソースフレームへアップサンプルし、
   robust percentile を黒（遠）と白（近）へ写像する。

成果物を再生成するには、文書化したエクスポーター環境を入れ、
`depthgen_fetch_model` を実行し、続けて `depthgen_build_model` または
`tools/build_zipdepth_model.py --self-test` を実行します。別のダイジェストを
出すツールチェーン変更は意図的にレビューし、マニフェスト、通知、完全性ピン、
ベンチマーク、プロバイダー一致記録をまとめて更新します。

### 发行 ONNX

发行二进制嵌入由 `tools/build_zipdepth_model.py` 生成的
`zipdepth_base_npu_dynamic.onnx`：

- 为兼容 ONNX Runtime 1.17.3 使用 ONNX IR 版本 8 与 opset 17；

导出器仅用 384×384 示例张量追踪图。动态轴保留在 ONNX 中，因此 Fast/Balanced、

将这些自由维度具体化；这是正确 Core ML 输出和提供程序优化所必需的。

Windows 构建将已验证字节存为 `RCDATA` 资源。通用 macOS 可执行文件的每个架构
切片将其存入只读 Mach-O 段。ONNX Runtime 直接从内存加载模型，不安装 ONNX
sidecar。嵌入字节的原始 SHA-256 在创建第一个会话前验证一次。

发行 ONNX SHA-256：

```text
0741a0d574609da33c5081b1054a2dd1e8845ecdbed9a5f69c48807c22400d59
```

### 输入输出约定

1. 用 Alpha 加权双线性采样将预乘源直接缩小为推理尺寸的 NCHW 张量；完全透明
   像素在推理中变为黑色。
2. 默认将输入视为 sRGB；若选择则用 sRGB OETF 编码线性输入。
3. 传入 `[0,1]` 范围的平面 RGB。ZipDepth 执行其学习/内部归一化；宿主不应用
   ImageNet 均值/标准差。
4. Fast 使用 512 像素全分辨率短边，Balanced 为 768，High 为 1080；Custom
   接受 256–2160 的任意整像素值。预览分辨率会先缩放标注短边，再将两个模型
   维度向上取整到 32 的倍数。因此 FHD 与 UHD 输入使用 1920×1088 和
   3840×2176 模型张量。
5. 以对齐角点的双线性将原始相对深度上采样到源帧，再将 robust 百分位映射为
   黑（远）和白（近）。

要重新生成产物，请安装文档中的导出环境，运行 `depthgen_fetch_model`，然后运行
`depthgen_build_model` 或 `tools/build_zipdepth_model.py --self-test`。若工具链
变更产生不同摘要，必须有意审查，并一并更新所有清单、声明、完整性固定、基准
和提供程序一致性记录。
